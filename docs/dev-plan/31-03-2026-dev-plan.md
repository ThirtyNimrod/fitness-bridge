## Proposed Roadmap (by priority tiers)

### Tier 1 — High Impact, Your Requests

#### 1. Fitbit Activity Sync (Pixel Watch 2 workouts)
The Fitbit Web API exposes `GET /1/user/-/activities/list.json` which returns all tracked activities — Badminton, Walk, Treadmill, Strength Training, Weightlifting, etc. from your Pixel Watch 2. This needs:

- **New method in `FitbitClient`**: `get_activities(before_date, limit)` hitting the activity log list endpoint
- **New method**: `get_activity_detail(log_id)` for per-activity heart rate zones, calories, GPS summary
- **Database schema change**: Add a `source` column (`strava` | `fitbit`) to the `workouts` table, and change the primary key to `(source, activity_id)` so Fitbit and Strava workouts coexist without collision
- **Activity type mapping**: Map Fitbit `activityTypeId` codes to categories (cardio/strength/sport/walking) so the dashboard and analysis layer can handle non-weightlifting workouts
- **Sync engine update**: Add a Fitbit activity sync path alongside Strava, with its own `last_synced_at` tracking (`sync_meta` source = `fitbit_activities`)
- **Non-Hevy workout records**: Fitbit activities won't have Hevy exercise data; they'll have duration, calories, HR zones, distance instead — the `build_session_record` function needs to handle both shapes
- **Dashboard + History**: Show all workouts regardless of source, with a source badge/icon

#### 2. Chat Management (Delete + Rename + Dynamic Names)
- **`delete_session(session_id)`** in database.py — cascade delete messages too
- **`rename_session(session_id, title)`** in database.py
- **Dynamic chat naming**: After the first assistant response, use the LLM to generate a 3–5 word title (e.g. "Bench press progress check") and auto-rename
- **Coach page UI**: Add a rename icon (pencil) and delete icon (trash) next to each session in the picker, with a confirmation dialog for delete

#### 3. Custom CSS + UI Polish
Streamlit supports injecting CSS via `st.markdown(unsafe_allow_html=True)`. Opportunities:

- **Custom theme colours**: Define a fitness-branded colour palette (dark bg, accent greens/oranges) in `.streamlit/config.toml` + supplemental CSS
- **Chat bubbles**: Style user/assistant messages with distinct backgrounds, rounded corners, avatar icons
- **Metric card styling**: Gradient or coloured backgrounds for readiness zones instead of plain `st.metric`
- **Sidebar branding**: Logo, styled connection status pills instead of emoji dots
- **Typography**: Custom font loading (Inter / Plus Jakarta Sans)
- **Animated readiness gauge**: CSS-only circular progress indicator for readiness score
- **Responsive tweaks**: Better mobile column stacking

# Fitness Bridge — Development Plan (March 31, 2026)
## Layer-by-Layer Enhancement Map

### 1. Agent Intelligence

| Gap | What's Missing | Impact |
|---|---|---|
| **No agent thinking visibility** | Users can't see *why* the router chose readiness vs progress vs coach | Trust & transparency |
| **No follow-up questions** | Agent never asks for clarification ("Which exercise do you mean?") | Better recommendations |
| **Single model lock-in** | `get_llm()` only initializes Ollama — no way to try different models | Flexibility |
| **No conversation memory decay** | `SHORT_TERM_WINDOW=8` is fixed — long technical discussions get truncated abruptly | Context quality |
| **Coach gets ALL tools** | coach_agent.py binds `readiness_tools + progress_tools + coach_tools` (9 tools total) — small LLMs struggle with large tool sets | Accuracy |
| **No multi-step planning** | Agents call one tool at a time reactively, never plan a sequence upfront | Smarter answers |

### 2. Analysis Layer — Missing Metrics

| Metric | Why It Matters |
|---|---|
| **Per-muscle-group weekly volume** | "Did I hit enough chest volume this week?" — currently impossible to answer |
| **1RM estimation** | Epley/Brzycki formula from `exercises_raw` sets data — enables strength tracking without max tests |
| **Rest day analysis** | How many days between sessions? Are you taking enough rest? |
| **Workout frequency/consistency** | Streak counting, missed-day detection, weekly session targets |
| **Intensity scoring** | ACWR currently only uses volume (kg) — ignoring duration entirely. A 30-min heavy session ≠ 90-min light session |
| **Deload detection** | Automatically flag weeks where volume dropped >30% — "planned deload or just lazy?" |
| **Sleep trend analysis** | `score_sleep()` only looks at one night — no 7-day rolling sleep trend |

### 3. Memory System

| Gap | Current State | Enhancement |
|---|---|---|
| **No fact management UI** | Facts are silently extracted and stored in `semantic_facts` — user can't see, edit, or delete them | Add a "My Profile" page showing all stored facts with edit/delete buttons |
| **Brittle fact extraction** | LLM returns JSON from free text, often fails silently (`except Exception: pass` in `extract_and_store_facts`) | Add validation, fallback patterns, and extraction success rate tracking |
| **No cross-session insights** | Each session is isolated — no learning across sessions like "you always ask about bench press on Mondays" | Aggregate patterns across sessions |

### 4. UI/UX Improvements

| Enhancement | Detail |
|---|---|
| **Calendar heatmap view** | Show workouts on a GitHub-style contribution grid — instant visual for consistency |
| **Dashboard time range selector** | Currently hardcoded to 28 days. Add 7d / 14d / 30d / 90d toggle |
| **Message actions** | Copy button, thumbs up/down reactions on assistant messages, retry button |
| **Chat search** | Search across all sessions for past coaching advice |
| **Onboarding flow** | First-time users see empty states everywhere. Guide them through connecting Strava → Fitbit → first sync |
| **Loading skeletons** | Replace `st.spinner` with skeleton placeholders that match the layout |
| **Workout comparison** | Side-by-side two sessions of the same workout type across dates |
| **Exercise database** | Autocomplete exercise names, proper muscle group mapping instead of relying on Hevy's free text |

### 5. Database & Data Layer

| Gap | Issue |
|---|---|
| **No indexes on date** | `get_workouts()` filters by `WHERE date >= date('now', ?)` with no index — will slow down as data grows |
| **No `workout_type` column** | Can't distinguish "Badminton" from "Bench Press Day" at query level |
| **No calories/HR zone columns** | Fitbit provides these but nowhere to store them |
| **No cascade delete on sessions** | Deleting a session doesn't delete its messages — `FOREIGN KEY(session_id) REFERENCES sessions(id)` exists but has no `ON DELETE CASCADE` |
| **No DB backup/restore** | Single SQLite file with no export or snapshot capability |

### 6. Sync & Data Pipeline

| Gap | Enhancement |
|---|---|
| **No sync progress feedback** | `SyncEngine.sync()` returns a final count but no progress callback — UI shows only a spinner |
| **No sync audit log** | No record of what was synced when, which activities failed, or why |
| **Background sync interval hardcoded** | 2 hours in `_background_sync_loop()` — should be configurable |
| **No partial sync recovery** | If sync crashes after 10/20 activities, those 10 are saved but next run may re-process them |

### 7. Security & Resilience

| Gap | Detail |
|---|---|
| **No rate limiting** | A user (or agent loop) could spam LLM calls infinitely — `MAX_TOOL_LOOPS=5` helps but no per-minute cap |
| **Token budget tracking** | No visibility into how many tokens each conversation consumes — important for cost control when moving beyond free Ollama |
| **No API quota monitoring** | Strava has 100 req/15min and 1000/day limits — no tracking or warning |
| **Credentials in .env only** | No UI-driven token refresh flow — tokens expire, user has to manually edit .env |
